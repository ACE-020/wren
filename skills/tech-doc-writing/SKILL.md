# 写技术文档

1. 动笔前先读 `references/style.md`，全文遵守其中的规范。
2. 先弄清读者是谁（使用者、开发者还是运维）、读完要能做什么，再决定结构。用户没说时直接问。
3. 结构依次是：一句话说明这是什么、前置条件、操作步骤、常见问题。步骤用编号列表，每步只做一件事。
4. 命令、路径、配置项放进代码块，并写明在哪个目录执行。
5. 修改已有文档时只改有问题的地方，并在回答末尾列出改了什么、为什么改。
