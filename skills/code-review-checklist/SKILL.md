# 代码审查清单

按以下顺序检查，只报告真实存在的问题，不要为了凑数列出风格偏好。

1. **正确性**：边界条件（空值、空列表、0、超长输入）、错误处理是否吞掉异常、并发与重复提交。
2. **安全**：拼接 SQL / shell / HTML、未校验的外部输入、密钥或个人信息写进代码或日志。
3. **可维护性**：重复代码、函数过长、命名与实际行为不符。
4. **测试**：改动的行为有没有测试覆盖；测试是否真的能在代码出错时失败。

输出格式：

| 级别 | 位置 | 问题 | 建议 |
|---|---|---|---|

级别取「必须改」「建议改」「可选」。最后用一句话给出总体结论：可以合并 / 改完再合并 / 需要重新设计。
